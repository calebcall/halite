Halite is configured through environment variables at startup and through in-app settings stored in the database. This page covers the environment variables. For the Salt-API connection and runtime poller tuning, see the [Settings](/features/settings) page.

## Environment variables

Set these in your `.env` file (which `docker compose` loads automatically) or pass them directly to the container.

### Database

<ParamField body="DATABASE_URL" type="string" required>
  SQLAlchemy async database URL.

  For `compose.yml` (Postgres): `postgresql+asyncpg://halite:halite@db:5432/halite`

  For `compose.sqlite.yml` (homelab): `sqlite+aiosqlite:////data/halite.db`
</ParamField>

### Sessions

<ParamField body="COOKIE_SECRET" type="string" required>
  Signing key for session cookies. Must be at least 32 characters. Generate one with `./scripts/gen-bootstrap-secret.sh`.
</ParamField>

<ParamField body="SESSION_TTL_MINUTES" type="integer" default="480">
  How long a session remains valid after the last request, in minutes. Defaults to 480 (8 hours).
</ParamField>

<ParamField body="COOKIE_SECURE" type="boolean" default="true">
  Controls the `Secure` flag on the session cookie.

  - `false` — cookie is sent over plain HTTP (use for local Docker testing at `http://localhost:8080`)
  - `true` — cookie is only sent over HTTPS (use in production behind a TLS proxy)

  The `compose.yml` profile defaults this to `true`; `compose.sqlite.yml` defaults it to `false`.
</ParamField>

### Inventory background scheduler

<ParamField body="INVENTORY_REFRESH_MINUTES" type="integer" default="0">
  When greater than `0`, the backend runs a periodic `refresh_packages(target='*')` every N minutes. Set to `0` to disable background refreshes — manual refreshes via the UI still work regardless of this setting.
</ParamField>

<ParamField body="INVENTORY_REFRESH_INITIAL_DELAY_S" type="integer" default="30">
  Seconds between process start and the first scheduled inventory refresh. Keep this above your healthcheck's grace period so the first refresh does not run before the Salt master has finished its own startup.
</ParamField>

### Bootstrap admin

<ParamField body="BOOTSTRAP_ADMIN_USERNAME" type="string" default="admin">
  Username for the bootstrap admin account. Only honored when no users exist in the database (i.e., on first boot).
</ParamField>

<ParamField body="BOOTSTRAP_ADMIN_PASSWORD" type="string" default="changeme">
  Password for the bootstrap admin account. Only honored when no users exist in the database. Change this before first start in any non-throwaway environment.
</ParamField>

### Networking

<ParamField body="LISTEN_HOST" type="string" default="0.0.0.0">
  The host address the uvicorn server binds to.
</ParamField>

<ParamField body="LISTEN_PORT" type="integer" default="8080">
  The port the uvicorn server listens on. Both compose profiles map this port to the host.
</ParamField>

<ParamField body="TRUSTED_PROXIES" type="string" default="">
  Comma-separated list of trusted proxy IP addresses or CIDR ranges used for `X-Forwarded-For` handling. Leave empty if Halite is accessed directly without a reverse proxy.
</ParamField>

### Logging

<ParamField body="LOG_LEVEL" type="string" default="info">
  Logging verbosity. Standard Python log level names: `debug`, `info`, `warning`, `error`, `critical`.
</ParamField>

<ParamField body="LOG_FORMAT" type="string" default="json">
  Log output format. `json` (structured, suited for log aggregators) or `text` (human-readable). A container restart is required to pick up a change to this value.
</ParamField>

## Salt-API connection

<Note>
  The Salt-API connection (URL, eauth backend, service credentials) is **not**
  configured via environment variables in current builds. It is stored in the
  database and managed through the in-app Settings page, where the password is
  encrypted at rest using your `COOKIE_SECRET` as the encryption key.

  The `SALT_API_*` lines in `.env.example` are commented out and marked "used
  in later plans" — they are not read by the application today.

  See [Settings](/features/settings) to configure the Salt-API connection and
  [How It Works](/concepts/how-it-works) for the architecture overview.
</Note>

## Inventory background scheduler

The background scheduler runs a fleet-wide package inventory refresh on a configurable interval. Two environment variables control its behavior:

- **`INVENTORY_REFRESH_MINUTES`** — set to a positive integer to enable automatic refreshes. `0` disables the scheduler entirely; you can still trigger refreshes manually from the Inventory page.
- **`INVENTORY_REFRESH_INITIAL_DELAY_S`** — adds a startup delay before the first refresh fires. This prevents the scheduler from querying the Salt master before it has fully initialized after a container restart.
